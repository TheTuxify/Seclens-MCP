# MCP USAGE & PROTOCOL RULES: SecLens-MCP
## راهنمای انطباق با پروتکل MCP و استاندارد ابزارها

---

### ۱. چرخه حیات نشست (Session Lifecycle)
سرور MCP باید چرخه حیات استاندارد را رعایت کند:
1. **Initialize (`initialize`):**  
   کلاینت نسخه پروتکل و توانمندی‌های خود را می‌فرستد. سرور با نام `seclens-mcp`، نسخه، و لیست قابلیت‌ها (`tools: {}`) پاسخ می‌دهد.
2. **Initialized Notification (`notifications/initialized`):**  
   تأییدیه نهایی برقراری نشست.
3. **فهرست ابزارها (`tools/list`):**  
   بازگرداندن اسکیماهای معتبر JSON Schema حاوی توضیحات دقیق، پارامترها و موارد الزامی (`required`).
4. **فراخوانی ابزار (`tools/call`):**  
   اجرای متد، مدیریت خطا و برگرداندن `content: [{"type": "text", "text": "..."}]`.
5. **Ping (`ping`):**  
   پاسخ سریع با شیء خالی `{}` برای تایید سلامت پروسه.

### ۲. قوانین اسکیما برای هوش مصنوعی (Schema Clarity)
- توضیحات (`description`) هر ابزار باید مشخص کند:
  - این ابزار دقیقاً چه کاری انجام می‌دهد.
  - پارامترها چه فرمتی دارند (مثلاً `https://example.com` یا دامنه خام `example.com`).
  - این ابزار در چه مواردی نباید استفاده شود.
- از تایپ‌های ساختاریافته (مانند `enum` برای فرمت خروجی) استفاده شود تا هوش مصنوعی ورودی نامعتبر تولید نکند.

### ۳. ایزولاسیون کانال ارتباطی Stdio
- **Stdout:** منحصراً و اکیداً برای پاسخ‌های JSON-RPC است. هیچ دستور `println!` یا لاگ متفرقه‌ای نباید به stdout فرستاده شود.
- **Stderr:** تمامی لاگ‌ها با ماژول `tracing` یا `eprintln!` به stderr هدایت می‌شوند. کلاینت‌های هوش مصنوعی پیام‌های stderr را نادیده می‌گیرند و ارتباط مختل نمی‌شود.
