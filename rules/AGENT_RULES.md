# AGENT RULES: SecLens-MCP (Rust Edition)
## راهنمای قوانین هسته برای ایجنت هوش مصنوعی

این فایل مشخص‌کننده استانداردهای مهندسی و خط قرمزهایی است که ایجنت باید در توسعه، بهینه‌سازی و معماری پروژه SecLens-MCP دقیقاً رعایت کند.

---

### ۱. اصل عدم توقف و مدیریت خطا در Rust (Zero-Panic Policy)
- استفاده از متدهای `unwrap()` و `expect()` در مسیرهای ران‌تایم (Runtime Code) اکیداً ممنوع است.
- تمامی خطاهای ورودی کاربر، شبکه، پارس JSON و تایم‌اوت‌ها باید با الگوی استاندارد `Result<T, E>` و ابزارهای خطایابی مدرن (`thiserror` یا `anyhow`) کنترل شوند.
- سرور MCP هرگز نباید با یک ورودی اشتباه یا قطعی شبکه کرش کند؛ در صورت بروز هر خطا، باید پاسخی تمیز در قالب ارور JSON-RPC به کلاینت بازگرداند.

### ۲. اصل ارزیابی غیرمخرب و ایمن (Passive & Non-Destructive Audit)
- ابزارهای این سرور با هدف ممیزی و ارزیابی امنیتی (Auditing & Reconnaissance) طراحی می‌شوند.
- ارسال ریکوئست‌های انبوه مخرب (DoS)، بروت‌فورس سنگین، یا بارگذاری پیلودهای تهاجمی ممنوع است.
- درخواست‌ها باید محدود، بهینه و با رعایت سقف ریکوئست در ثانیه (Rate-Limit Friendly) ارسال شوند.
- تایم‌اوت مشخص (پیش‌فرض: ۵ الی ۸ ثانیه) برای تمام ارتباطات شبکه الزامی است.

### ۳. استانداردهای انطباق با پروتکل MCP (Model Context Protocol)
- سرور باید پروتکل استاندارد **JSON-RPC 2.0** را روی ورودی و خروجی استاندارد (`stdin` / `stdout`) بدون ارسال هرگونه لاگ متفرقه به stdout پیاده‌سازی کند.
- تمامی پیام‌های لاگینگ و عیب‌یابی باید منحصراً به **`stderr`** فرستاده شوند تا پکت‌های JSON-RPC شکسته نشوند.
- خروجی هر ابزار باید شامل یک خلاصه مارک‌داون تمیز و ساختاریافته برای انسان، به همراه جزئیات فنی دقیق باشد.

### ۴. کارایی حافظه و هم‌روندی (Concurrency & Performance)
- برای تسک‌های شبکه‌ای هم‌زمان از استخر اتصالات `reqwest` با موتور ناهمگام `tokio` و `rustls` استفاده شود.
- تعداد ارتباطات هم‌زمان باید با سمافور (`tokio::sync::Semaphore`) کنترل شود تا منابع سیستم یا سرور هدف قفل نشوند.
- تخصیص حافظه (Memory Allocations) تا حد امکان مینیمال باشد و از داده‌های قرض‌گرفته‌شده (`&str`, `Cow`) به جای کلون‌های بی‌مورد استفاده شود.

### ۵. زبان و لحن خروجی (Tuxify Brand Persona)
- متون توضیحات ابزارها، خروجی‌های گزارش و مستندات باید رسمی، مهندسی، مسلط و بدون حاشیه باشند.
- از هیچ ایموجی اضافی در کدهای هسته یا گزارش‌های رسمی استفاده نشود.
